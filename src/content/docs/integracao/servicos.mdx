## A ordem das chamadas

Toda integração segue a mesma sequência:

1. **`GET /api/token`** apresentando o certificado A1 em mTLS → devolve um JWT
2. **`POST /api/fhir/r4/Bundle`** com o token no header
   `X-Authorization-Server` → envia o documento

Para acessar dados clínicos de um indivíduo, o guia narrativo anterior descreve
um passo a mais: o `POST /api/contexto-atendimento`, que produz o token de
autorização de contexto assistencial. O Guia de Implementação de outubro de 2026
não menciona esse serviço, então confira antes de depender dele.

:::caution[O header não é `Authorization`]
O barramento espera **`X-Authorization-Server`**. Usar o `Authorization`
convencional é o erro mais comum da primeira tentativa, e a mensagem de erro
resultante costuma ser genérica e não apontar o header. Veja
[autenticação](/integracao/autenticacao/).
:::

## Documento clínico é imutável

Repare que substituir também é um `POST` de Bundle, não um `PUT`. Isso não é
descuido de API: conceitualmente, um documento clínico é um instantâneo
assinado. Correção não edita o documento original, gera um novo que substitui o
anterior.

Três regras do Guia de Implementação que mudam o desenho do seu sistema:

- **Guarde os dois identificadores** de cada documento: o local, que o seu
  sistema gerou, e o ID RNDS, que volta no header `location` do envio. Sem eles
  não há como consultar, substituir nem excluir depois.
- **A substituição só pode ser feita uma vez por documento.** O novo Bundle
  repete o identificador local do original e aponta para o ID RNDS dele em
  `Composition.relatesTo`, com `code: replaces`.
- **A exclusão é lógica**, por `DELETE` com o ID RNDS, no endpoint da mesma UF
  do envio, e só vale para documento com status `final`.

Se o seu modelo de dados assume atualização em campo, essa é uma diferença de
desenho que vale acertar antes de escrever código.

## Onde está o contrato completo

Esta página é um índice. O comportamento de cada operação, com exemplos de
requisição e de resposta, está na
[página de integração do Guia de Implementação](https://fhir.saude.gov.br/pt-BR/integracao.html).
Os códigos de erro estão no
[catálogo de mensagens e erros](https://fhir.saude.gov.br/pt-BR/CodeSystem-RNDSErros.html).

O **Manual de Integração do Barramento**, em PDF aberto pelo DATASUS, é a
referência mais antiga:
[SOA-RNDS_ManualIntegracaoBarramento_vSite.pdf](https://datasus.saude.gov.br/wp-content/uploads/2020/04/SOA-RNDS_ManualIntegracaoBarramento_vSite.pdf).
Confira a data no cabeçalho antes de confiar: circulam versões antigas do mesmo
arquivo.

Para ver a forma das requisições antes de ter acesso, a
[coleção Postman do kyriosdata/rnds](https://github.com/kyriosdata/rnds/blob/master/tools/postman/rnds-postman-collection.json)
é boa leitura. Ela é anterior ao Guia de Implementação de outubro de 2026, então
os serviços novos desta página não estão nela.
